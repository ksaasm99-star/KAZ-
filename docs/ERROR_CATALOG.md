# KAZ Error Catalog

هذا الكتالوج هو المرجع الموحّد لأخطاء KAZ التي تظهر في API وواجهة التشخيص. كل استجابة خطأ حساسة تحمل `error` و`traceId` و`timestamp`، ويمكن تتبعها في Evidence Ledger.

| الرمز | السبب | الرسالة للمستخدم | الحل المقترح |
|---|---|---|---|
| `KAZ-AUTH-001` | غياب أو عدم صحة Bearer token | المصادقة مطلوبة لهذه العملية. | أضف `KAZ_OWNER_TOKEN` للخادم واحفظ نفس القيمة في إعدادات KAZ. |
| `KAZ-PROVIDER-001` | مزود الذكاء غير متاح أو غير مهيأ | مزود الذكاء غير متاح حاليًا. | افحص `/api/health`، ثم شغّل المزود أو اضبط إعداداته. |
| `KAZ-PROVIDER-002` | النموذج المطلوب غير موجود | النموذج المطلوب غير متاح لدى المزود. | ثبّت النموذج أو اختر نموذجًا مسجلًا ومتاحًا. |
| `KAZ-FACTORY-001` | فشل التخطيط أو إرسال بناء المشروع | تعذر إكمال عملية بناء المشروع. | راجع تفاصيل التشخيص وسجل البناء قبل إعادة المحاولة. |
| `KAZ-NETWORK-001` | فشل اتصال خارجي مسموح | تعذر الوصول إلى المصدر الخارجي. | افحص HTTPS وNetworkBroker والموافقة الصريحة. |
| `KAZ-SANDBOX-001` | فشل العزل أو غياب Bubblewrap | تعذر تشغيل الأمر داخل العزل الآمن. | ثبّت/فعّل Bubblewrap rootless ثم أعد الفحص. |
| `KAZ-DB-001` | تعذر فتح SQLite أو قراءة السجل | ذاكرة KAZ الدائمة غير متاحة. | افحص مساحة القرص وصلاحيات مجلد `.data` ثم أعد التشغيل. |
| `KAZ-EMERGENCY-001` | حالة الطوارئ مفعلة | التنفيذ متوقف لحماية المشروع. | راجع سبب الإيقاف وأعد تفعيل التنفيذ من مسار الطوارئ المصرح به. |

## قواعد العرض

لا تعرض KAZ الأسرار أو محتوى Authorization في الرسائل أو Evidence Ledger. يستخدم `traceId` للربط بين الواجهة، API، وسجل الأدلة، بينما تبقى التفاصيل الفنية داخل `details` في السجل عند الحاجة.
